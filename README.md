# Three Answer（3人協力型クイズゲーム）

カプリティオチャンネル考案のカードゲームをWebアプリ化したものです。
3人のプレイヤーがそれぞれ10枚のひらがなカードを持ち、クイズの正解を
「場に出したカードの連結」で作る協力ゲーム。序盤は1枚、中盤は2枚合体、
最後は3枚合体。**必要な人が過不足なく出せたときだけ正解**になります。

## 機能

- ルーム作成 & URL共有で参加（[codenames.game](https://codenames.game/) 方式。開くだけで参加）
- 正解時の紙吹雪演出（`canvas-confetti`）
- 名前設定、A/B/C席への着席、観戦者モード（「全手札を見る」トグル付き）
- 3人全員がアクティブなブラウザで揃って初めて開始可能
- 誰かのタブが非アクティブになると**カウントダウンごと自動一時停止**、復帰でシームレス再開
- 問題文のタイプライター表示 + 制限時間（30/45/60/90秒、ロビーで設定）
- 全員同期の判定演出画面（毎問、正解と解説を表示）
- 最終スコアと全問履歴画面（全員の手札公開、未使用カード表示）
- 問題セットは5種類（難易度グラデーション付き）。同じルームで連戦可能
- 複数ルーム同時開催可

## ローカルで動かす

```bash
npm install
npm run dev
```

Redisの環境変数が無い場合は自動で**インメモリストア**にフォールバックするので、
そのまま `http://localhost:3000` で動作確認できます（タブを複数開けば3人分試せます）。

## Vercelへのデプロイ

1. このリポジトリをGitHubにpushし、Vercelでimportする。
2. Vercelダッシュボード → Storage（Marketplace）→ **Upstash Redis** を追加してプロジェクトに接続する。
   - 接続すると `KV_REST_API_URL` / `KV_REST_API_TOKEN`（または
     `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`）が自動設定されます。
     アプリはどちらの変数名でも動きます。
3. Deploy。以上です。

> 環境変数が無いままVercelにデプロイすると、サーバーレスインスタンス間で
> 状態が共有されず正しく動きません（起動はします）。必ずRedisを接続してください。

## テスト・検証

```bash
npm test               # エンジン・判定・タイマーのユニットテスト
npm run validate-sets  # 問題セットの機械検証（重複・連結一致・別解の曖昧性など）
npm run build          # 本番ビルド
```

## 問題セットの作り方（データパイプライン）

問題は `data/sets/set1.json`〜`set5.json` に静的データとして入っています。
これらはローカルMySQLのクイズDB（`quiz.quizzes3`、約2.4万問）と
分類語彙表（`corpus.bunruidb`）から、以下の手順で作っています（`tools/` 配下）。

**核となる考え方**は「**クイズの正解として頻出＝複数の問題を作れるワード**を軸に手札を組む」ことです。
1枚のカードに問題候補が何通りもあるので、その中から「**他人の札と同じカテゴリになる問題文**」を
選べます。これがこのゲームの肝である引っかけ（誰が出すべきか悩む状況）を生みます。

1. `tools/wordpool.mjs` — 答えの読みごとに「何問作れるか」を集計して頻出ワードを抽出し、
   さらに分類語彙表の意味分類から**同カテゴリの兄弟語（＝罠候補）**を紐づける。
   頻出語同士の連結でできる合体語（2枚・3枚）も列挙する
2. `tools/sib.mjs` — 設計時の検索。`--word <読み>` でその語で作れる問題一覧、
   `<読み>` で同カテゴリの罠候補、`--pair <語1> <語2>` で合体語の実在確認
3. 頻出語から手札30枚を組み、全20問に罠を割り当てる（`traps` フィールドに記録）
4. `npm run validate-sets` — 構成・連結の一致・**別の出し方で綴れる曖昧性**・
   解説の手札ネタバレ・**罠の網羅**・連続無関心区間を機械検証
5. `npm run check-sources` — 各問題の `source: "quizzes3:<id>"` が実在し、
   読みがDBと一致するかを検証（要ローカルDB）

セットを自作する場合は `data/sets/setN.json` を同じスキーマで書き、
`npm run validate-sets` が通ることを確認してください
（スキーマは `src/lib/types.ts` の `QuestionSet`、
 設計原則と罠の条件は `DESIGN.md` §8 を参照）。
